# Contributing to The Playwright Engineering Handbook

First of all, thank you for your interest in contributing to **The Playwright Engineering Handbook**.

This repository exists to provide high-quality educational resources, enterprise Playwright examples, framework implementations, and AI-assisted browser automation samples for the software engineering community.

Every contribution, regardless of size, is appreciated.

---

# Ways to Contribute

You can contribute by:

* Fixing bugs
* Improving documentation
* Correcting typos
* Improving code examples
* Adding enterprise examples
* Enhancing Playwright MCP samples
* Reporting issues
* Suggesting improvements
* Adding interview questions
* Improving CI/CD examples

---

# Before You Start

Please:

* Search existing Issues before opening a new one.
* Keep changes focused on a single topic.
* Follow the coding style used throughout the repository.
* Test all code before submitting a Pull Request.

---

# Development Setup

Clone the repository:

```bash
git clone https://github.com/parthkandpal/playwright-engineering-handbook.git
```

Install dependencies:

```bash
npm install
```

Install Playwright browsers:

```bash
npx playwright install
```

Run the test suite:

```bash
npx playwright test
```

---

# Coding Guidelines

Please follow these principles:

* Write readable TypeScript.
* Prefer Playwright best practices.
* Use semantic locators whenever possible.
* Avoid duplicated logic.
* Follow SOLID principles.
* Keep examples simple and educational.
* Add comments only when they improve understanding.

---

# Documentation Guidelines

Documentation should:

* Be beginner friendly.
* Remain technically accurate.
* Follow enterprise engineering practices.
* Use consistent terminology.
* Match the writing style used throughout the book.

---

# Pull Request Process

1. Fork the repository.
2. Create a feature branch.

```bash
git checkout -b feature/my-improvement
```

3. Commit your changes.

```bash
git commit -m "Improve Playwright fixture example"
```

4. Push the branch.

```bash
git push origin feature/my-improvement
```

5. Open a Pull Request.

---

# Reporting Issues

When reporting issues, please include:

* Description
* Expected behavior
* Actual behavior
* Steps to reproduce
* Screenshots (if applicable)
* Environment details

---

# Code of Conduct

Please be respectful, professional, and constructive.

We welcome contributors from all backgrounds and experience levels. Healthy technical discussions are encouraged, but personal attacks, harassment, or disrespectful behavior will not be tolerated.
